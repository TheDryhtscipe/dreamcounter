- **Date:** 2026-11-14. **Status:** accepted by Claude as technical design (autonomous lane). Open to change by the project lead. Bead dreamcounter-86c25d (P4.4). Follows D4 (doc-tmq), D11 (doc-d9s), D17 (doc-gqz) and D18 (doc-g97).
- **Decision:**
  1. **A library crate does the step.** `dc_driver::run_iteration` takes the run's tasks with their signatures, the library, each task's frontier, the verified candidates of the iteration, the frontier size K, and a Stitch runner. It returns the new library entries, the new frontiers, and an `IterationReport`. It keeps no state and writes nothing. dc-mcp calls it and commits the result (bead dreamcounter-967d1d).
  2. **Checks.** Each library entry must parse, expand and type. Each frontier member must parse, print again, be closed, expand, and type against its task's signature. A failure there is an error: the run's state is wrong. A candidate that fails the same checks is reported as invalid and left out, so one bad candidate does not stop the step.
  3. **Frontiers.** Each task's pool is its frontier, then its candidates in the order they came in. Of the programs with one expansion, the pool keeps the cheapest, and the earliest of those on a tie; the others are its duplicates. So a candidate that uses the library to spell a member more cheaply replaces the member: Stitch does not rewrite programs with abstractions the library already has. The pool is sorted stably by the cost Stitch gives the program with its default costs (1 for a lambda or an application, 100 for a variable, a parameter, a primitive, a literal, or a library use), and the first K are kept.
  4. **Selection is λ = 0.** P4 is the LILO-like baseline. Every kept program goes to Stitch with its task's label. Stitch counts only the cheapest rewrite of each task, which is the per-task minimum of D4's J(L) at λ = 0. The cost-aware selection of D4 (λ, the timeout penalty, refusals) is P5, and replaces this selection step.
  5. **Programs the bridge refuses.** A program that cannot be encoded or is too deep is left out of the Stitch run and stays in its frontier as it is.
  6. **Failed and interrupted runs.** A run stopped at its time or memory limit, a Stitch panic, or bad output skips compression for the iteration: the frontiers still update, the library does not change, and the report says why. A cancelled run, or a worker that cannot be started or read, returns `DriverError::Interrupted`. The caller must then not finish the iteration, and runs the step again.
  7. **Library update.** Each new abstraction gets a scheme inferred from its body with the earlier ones. The new abstractions are cut at the first that does not type or is too large to print (an abstraction can be a few lambdas larger than the programs it was found in). A rewritten program is accepted only if it types against its task's signature and expands to what its original expands to; otherwise the original stays. New abstractions after the last one an accepted rewriting uses are cut. Each frontier is then sorted again under the new library.
  8. **Replay.** When Stitch finishes, the same input gives the same outcome. A worker run can end at a limit depending on the machine, so a replay reads the logged outcome and does not run the step again.
  9. **The prelude (bead dreamcounter-6b1cd9).** Proposers' programs are compiled with the prelude, so they use its functions as `Term::Lib(LibId(PRELUDE_LIB_BASE + i))`. `IterationInput` takes `prelude: Option<&Prelude>`. `None` is the prelude-off ablation: a prelude reference is then an unknown library. With a prelude, library entries, members, candidates and new abstractions are typed with `Prelude::with_libs` over the learned schemes. They are expanded prelude first, learned abstractions second. Stitch gets each prelude function as an opaque token with the prelude's own name, never its body. So abstractions and rewritten programs keep the references, and the run's state holds references, not definitions. The `Stitch` trait takes the prelude. dc-compress gains `compress_with`, `compress_isolated_with` and `accept_steps_with`, which build the names table from the prelude and expand it before the learned expander. The old functions pass no prelude. dc-compress exports `library_names` and `expand_prelude`, and the driver uses them. So the cost the driver gives a program and the text Stitch sees come from one table.
  10. **Prelude fingerprint.** A prelude reference is positional. A stored program keeps its meaning only against the prelude it was compiled with. If `prelude.dc` is reordered, two definitions of the same type, such as `max` and `min`, can swap ids, and the checks above still pass. `Prelude::fingerprint` gives a 64-bit FNV-1a hash of each definition's position, name, and closed term. It is the same in every process, and comments and layout do not change it. The run stores it and compares it before it uses stored programs (dreamcounter-967d1d). The driver keeps no state, so it does not check the fingerprint.
- **Alternatives:**
  - (h) Store prelude references by name instead of position. Rejected for now: `sexpr` prints and parses a library reference as `lib_N`, and a name form would change the core text format of every program. A fingerprint finds the mismatch with no format change.
  - (i) Keep dc-surface out of dc-compress's dependencies, with a trait or a plain table for the names and the expansion. Rejected: dc-surface depends only on dc-core, the worker binary calls no prelude code, and a trait adds a seam for one implementation.
  - (f) Number the prelude after the learned library, as extra arity-0 entries, so that dc-compress needs no change. Rejected: Stitch would see `fn_k` tokens instead of the prelude's names, and every output term would need its ids renumbered back, which is a second place for an off-by-one.
  - (g) Put the prelude in `DriverConfig`. Rejected: the config is `Copy`, and the prelude is data the run owns, like the library. The input already borrows the run's data.
  - (a) Build the MCP tool in this bead, on a stand-in format for submissions. P4.2 (dreamcounter-9c8980) would then have to fit it. Rejected: P4.2 decides how submissions are stored.
  - (b) Select one program per task before Stitch, then compress. Stitch already takes the minimum per task over the programs it is given, so this loses programs that become the cheapest after rewriting.
  - (c) Rank frontiers by node count. Stitch's own costs rank programs the way Stitch scores them.
  - (d) Retry a failed Stitch run with fewer or shorter programs. Left out until real runs show how often runs fail.
  - (e) Trust the bridge's expansion check. The driver checks again, so a runner that skips the check cannot change a program.
- **Why:** a pure step can be tested without a server, and its tests use stand-in Stitch runners to reach cases real Stitch rarely gives. Type checking after rewriting is needed because a rewriting keeps the expansion but not always the type (dc-core test `a_parameter_used_at_two_types_can_make_the_refactored_program_untypable`).
- **Limits:**
  - The bridge returns only the programs rewritten with every abstraction it accepted. A program that uses a cut abstraction keeps its original form, even when the earlier abstractions alone would give a rewriting that types.
  - A typed abstraction that no accepted rewriting uses stays in the library if a later one is used.
  - The driver checks candidates by syntax, expansion and type only. Their behaviour on the task's examples is checked before they reach it (P4.2).
  - A worker killed from outside, for example by the system's out-of-memory killer, counts as a failed run, not an interruption. The iteration then finishes without compression, as it does at a time limit.
  - K has no default. The run sets it.
  - The `Isolated` runner has no test in this crate. The worker itself is tested in dc-compress, with and without a prelude. The wiring bead tests the path end to end.
- **Left for later beads:**
  - **dreamcounter-967d1d:** the dc-mcp binary serves the worker; the server runs the step under `spawn_blocking`, sets the cancel flag on shutdown, and commits FrontierSet, LibraryExtended, the report as a log record, and IterationFinished in one record. LibraryEntry gains the arity and RunConfig gains K, which changes the journal format. The report types refuse unknown fields, so a later field needs a format version or a default. The run also stores `Prelude::fingerprint` when it starts, and refuses to load stored programs under a prelude with another fingerprint.
  - **dreamcounter-183fbb (P5):** the cost-aware selection.
